# AMD Radeon F32 Processor Module for Ghidra

This processor module is meant to decode the ISA of the custom "F32" CPU core
used for various management tasks in many AMD Radeon GPUs.

Based on the information in [radeon-tools][radeon-tools] and [this
presentation][33c3].

**NOTE**: Ghidra-Rare has since verified and completed this module (decoding, p-code, a
firmware-image loader); see [GHIDRA-RARE.md](GHIDRA-RARE.md) for the results, the tests and the
modelling decisions that nothing public settles, and [CREDITS.md](CREDITS.md) for provenance.
Prebuilt zips for Ghidra 12.1.3, 12.1.4 and 12.2 are on this repository's Releases page.

The original author's to-do list, with its status:

- [x] Verify that the disassembly output matches that generated by `f32dis.py`: 0 differences
  over 673,792 words (all opcode/field combinations plus 100,000 random words), in both languages.
- [x] Refactor instruction decoding: rewritten around small sub-tables; every one of the 124
  constructors is reached by the test corpus.
- [x] Add semantics for push/pop instructions to make the stack work (dummy stack pointer in the
  data space; the real stack layout is unknown).
- [x] Handle memory accesses to the different memory spaces: the plain, `reg`, `mem` and `unk`
  operands now address four separate word-addressed spaces (DM, RM, SM, XM); `ldd`/`std`,
  `stm` (repeat `ctr` times) and the 64-bit forms (`addd`, `andd`, `lsra`/`lsrad` ...) have p-code.
- [x] Add file loader to automatically identify old-style vs. new-style firmware images: new
  `AMD Radeon F32 microcode` loader (header detection for new-style, plausibility checks for
  old-style; picks `F32:LE` or `F32:BE`, maps the code at IM:0).
- [x] Enable the file loader to add labels for the branch addresses listed in the table at the
  end of the firmware image: the table gets its own block and every handler is labelled `PKT_0x<n>`
  and made an entry point.
- [ ] Adjust calling convention to match observed calling convention: remaining. The microcode is
  hand-written with global register allocation; no calling convention exists to model (the default
  prototype no longer uses r1, whose reads pop the command queue).
- [ ] Confirm instruction semantics on real hardware: remaining (no hardware access); the choices
  are listed in GHIDRA-RARE.md.
- [x] Confirm the register sizes and 32-bit/64-bit behavior: modelled (32-bit operations write the
  zero-extended low half of the 64-bit register), but only the *encodings* of the 32/64-bit forms are
  verified, not the hardware behaviour.
- [x] Confirm memory byte ordering: the processor addresses 32-bit words and has no byte access, so
  byte order is unobservable; `ldd`/`std` put the low half of the register in the lower-numbered word,
  explicitly, so the big- and little-endian-instruction languages agree.

Bugs fixed in this version: the "big endian instructions" language was compiled big-endian but declared
little-endian in its language definition, so every 32-bit truncation (`rs:4`) took the wrong half of a
register; 64-bit `andd`/`orrd` masks were printed truncated to 32 bits; `setgt`/`setge` compared unsigned;
writes to `r0` were written through a constant.

## Build and Install

```
$ git clone https://github.com/cyrozap/ghidra-radeon-f32.git
$ cd ghidra-radeon-f32
$ GHIDRA_INSTALL_DIR=/path/to/ghidra_12.1.4_PUBLIC gradle buildExtension
```

The `dist` directory will now contain the extension zip file that you can
install into Ghidra.
